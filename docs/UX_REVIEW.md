# 产品交互设计评审（学习闭环上线后第一轮收拢）

> 范围：web-ui / desktop-app 共用的用户面（学习扩展为主，审校侧为辅）。
> 依据：对 `App.vue` / `LearningPanel.vue` / `ErrorList.vue` / `ResultsPanel.vue`
> 与后端契约（`/gec/mistakes` / `/gec/review` / `/gec/analysis`）的实际走查。
> 状态：评审结论，未实现项按优先级标注。

## 1. 设计原则（判定问题的尺子）

1. **闭环可见**：用户每个动作的下游效果要当场可见（采纳 → 进了错题本 → 今天有题要复习）。
2. **术语说人话**：界面上不出现内部模型词汇（basis、confirmed、detected、FSRS）。
3. **一个概念一个名字**：同一事物在导航 / 卡片 / 徽章里必须同名。
4. **可反悔**：破坏性或影响记忆状态的操作要能低成本撤销。
5. **复习队列尊重记忆科学**：到期最久的先出，不是最新的先出。

## 2. 信息架构现状

| 顶层导航 | 内容 | 门控 |
|---|---|---|
| 检测 | 编辑器 + 错误列表（画像不在检测页——走查代码确认，仅练习页有） | 全员 |
| 练习与复习 | 全局错题本 + 今日复习卡 + 掌握度 | 学习扩展 |
| 载体审校 | 图片 / PDF / Word 审校 | 编校扩展 |
| 规则 / 知识 / 进化 | 运营面 | 平台运营扩展 |
| 设置 | 档案（母语 / CEFR）+ 运行时设置 | 全员 |

## 3. 旅程走查（学习者主线）

粘贴文稿 → 检测 → 逐条采纳 / 放弃 → 错题进**全局错题本** → 「练习与复习」复习卡
（挖空 → 揭晓 → 记住 / 没记住）→ FSRS 排期 → 到期 ≥30 天 = 已掌握。

断点与摩擦（编号 = 问题清单）：

- **L1 采纳时闭环不可见**：采纳成功的反馈没有提到错题本；用户不知道
  「采纳」还有学习副作用，也不会主动去看「练习与复习」。
- **L2 复习无召回钩子**：顶层导航「练习与复习」不显示今日到期数；到期 0 与
  从未看过，用户感知相同。
- **L3 复习队列排序违反记忆科学**：`/gec/review` 按最近出现（`last_id DESC`）排序，
  应是**到期最久优先**（新卡其次）。越期的题越该先练。
- **L4 挖空可能泄露答案**：`original` 不在句子里时直接整句展示（答案就在句面上），
  复习有效性归零。
- **L5 复习点错不可反悔**：「记住 / 没记住」立即写 FSRS 记忆状态，无撤销窗口；
  误一次「记住」会把没掌握的题推到远期。
- **L6 二键评分浪费了 FSRS**：FSRS 的记忆科学优势来自评分粒度；只有
  记住 / 没记住时，调度精度约等于 SM-2。
- **L7 复习无当日节奏感**：一次一题、无「今日 x/y」进度与收尾反馈，复习像抽查不像练习。
- **L8 错题本量大后不可浏览**：无「待复习 / 全部 / 已掌握」过滤、无搜索；
  类型分组全量展开。

## 4. 旅程走查（画像与术语）

- **P1 两套画像并存无解释**：~~检测页显示**会话**习惯性错误，练习页显示**全局**画像~~
  （实现走查更正：检测页实际没有画像卡片，并存问题不存在；只剩练习页一处画像，
  已为其补范围标签，见 C1）
- **P2 内部词汇外泄**：「画像基于确认错误（误报与未采纳建议不计入）」是工程口径，
  用户读不懂「确认 / 误报」。
- **P3 术语不统一**：徽章「待复习 / 复习中 / 已掌握」vs 按钮「记住 / 没记住」vs
  导航「练习与复习」vs 卡片「错题本 / 今日复习」。
- **P4 删会话的后果无告知**：删会话会移除该会话贡献的错题（复习进度保留、重现复活）——
  这是刻意设计，但确认对话框没说明，用户会以为「错题丢了」。

## 6. 明确不做 / 暂缓

- 复习排队的「自选顺序 / 随机模式」：伪需求，尊重算法默认序。
- 错题本手动编辑 / 删除单条：会破坏单一事实源（错题来自采纳记录）；如要「不想要这条」，
  应做「忽略」标记而非删除（未列入近期切片）。
- 多邻国式连击 / 排行榜：与本地单人产品气质不符，先靠 A1/B2 建立节奏感。
